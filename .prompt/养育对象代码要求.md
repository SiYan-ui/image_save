# 养育对象代码要求

> 本文汇总当前项目中与“养育对象”相关的已确认要求。开发时应同时遵守 `.prompt/P0级要求.md` 中的项目级约束；更完整的产品背景可参考 `.prompt/[落地版]产品方案-养成存钱罐.md`。

## 1. 支持的养育对象

当前支持以下四类养育对象：

| 类型 | Kotlin 枚举值 | 说明 |
|---|---|---|
| 男婴 | `BABY_BOY` | 男孩养育对象 |
| 女婴 | `BABY_GIRL` | 女孩养育对象 |
| 猫咪 | `CAT` | 宠物猫养育对象 |
| 狗狗 | `DOG` | 宠物狗养育对象 |

养育对象类型统一使用 `CreatureType` 表示，不要使用无约束字符串在业务代码中传递类型。

## 2. 养育对象资料模型

养育对象资料使用 `CreatureProfile` 表示，当前已知核心字段包括：

- `id`：对象唯一标识。
- `name`：用户为养育对象设置的名称。
- `type`：养育对象类型，使用 `CreatureType`。
- `birthTimeMillis`：出生或创建时间，使用毫秒时间戳。
- `ageInMonths`：当前月龄。
- `totalExpense`：累计花销。

后续扩展字段时，应保持现有字段含义和兼容性，不要随意修改已有字段类型或枚举值。

## 3. 事件与花销逻辑

项目使用 `EventEngine` 处理养育事件和花销计算：

- 根据养育对象类型和当前月龄判断应触发的事件。
- 使用 `getTriggeredEvents(profile, ageInMonths)` 获取当前触发事件。
- 使用 `totalFor(profile, ageInMonths)` 计算累计花销。
- 不同类型的养育对象可以拥有不同的事件、金额和触发月龄。
- 事件逻辑应集中在业务层，不要直接写进 Activity 或 XML 布局。

当前业务代码文件：

`app/src/main/java/com/example/image_save/EventEngine.kt`

## 4. 主场景要求

当前主页为程序主场景，要求如下：

- 主页面只显示 `livingroom.png` 作为客厅背景。
- 原主页中的养育对象切换按钮、名称、月龄、累计花销和事件列表均不显示。
- 原始图片位置为：`img_stay/livingroom.png`。
- Android 运行时使用的图片资源位于：`app/src/main/res/drawable/livingroom.png`。
- 主场景布局文件为：`app/src/main/res/layout/activity_main.xml`。
- 主场景 Activity 为：`app/src/main/java/com/example/image_save/MainActivity.kt`。
- 清除主页控件不等于删除养育对象的数据模型和事件引擎；相关业务代码应继续保留，供后续功能使用。

目前只确认客厅背景为主场景，以下内容尚未确定，未经明确要求不要自行实现：

- 事件弹窗、物品栏、消费统计和提醒界面。

## 6. 实现约束

实现养育对象相关功能时必须遵守以下规则：

1. 使用 Kotlin 和 XML View，不擅自迁移到 Jetpack Compose。
2. 代码写在 `app` 模块下，默认包名为 `com.example.image_save`。
3. 业务逻辑与界面逻辑分离，不要把事件计算堆积在 `MainActivity` 中。
4. 不使用废弃 API，并兼容项目当前的 `minSdk = 24`。
5. 不自行升级 AGP、Gradle、SDK 或现有依赖版本。
6. 不随便新增第三方依赖；确需新增时，先说明依赖名称、版本、用途和影响。
7. 当前功能不需要网络，不要自行添加网络权限或网络依赖。
8. 涉及图片读写时，优先使用 `MediaStore`、系统选择器或应用专属目录等现代方案。
9. 如确需危险权限，必须适配当前 `targetSdk` 并在运行时申请，仅申请最小必要权限。
10. 修改后至少执行项目构建，检查 Kotlin、XML、Manifest 和资源引用是否正确。

## 7. 当前已确认与未确认事项

### 已确认

- 支持男婴、女婴、猫咪、狗狗四种类型。
- 已存在 `CreatureType`、`CreatureProfile` 和 `EventEngine` 相关业务代码。
- 事件和累计花销与养育对象类型、月龄相关。
- 当前主页只使用客厅图片作为主场景。
- 项目当前使用 Kotlin、XML View 和 AppCompat。

- 数据是否需要持久化，以及采用何种持久化方案。
- 是否允许同时创建多个养育对象。
- 角色状态、成长速度和时间推进规则。
- 图片素材命名、分辨率和适配规则。
- 事件确认后对累计花销、物品和状态产生的具体影响。

在以上事项得到明确需求前，应保持现有实现，不根据猜测扩展功能。
